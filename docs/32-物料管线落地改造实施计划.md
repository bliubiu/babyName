### 1.1 为什么必须先做 P-1

`docs/31 §二` 的逐行复核发现：**当前 SQLite 侧的 `hanzi_data` 与内存 `HanziData` 已经不一致，且是静默的**。
若直接进入 P0/P2（「校验上移」「SQLite 为唯一源」），这些缺陷会被一并烘焙进「权威库」，且届时
「双读一致」这条 ADR-003 的核心断言将**无法通过**。因此 P-1 是**正确性前置**，不是可选优化。

四项前置与阻断关系：

```
P-1.1 upsert 语义      ─┐
P-1.2 字段投影补全      ─┼─→ 阻断 ADR-003「双读一致」断言、ADR-008「唯一源」验收
P-1.3 康熙落点决策      ─┤
P-1.4 checksum 门控    ─┘─→ 阻断 ADR-006 热更新 diff、ADR-010 版本门控
```

### P-1.1　持久化写入语义改为 upsert（ADR-011）

**问题**：`seedHanziData` 用 `INSERT OR IGNORE`，导致 ① 物料字段修订不传导 ② 删字不删除
③ 每次启动仍全表扫描尝试插入。`docs/31 §2.3.6` 原描述「upsert」失实。

**改动清单**

| # | 文件 | 改动 |
|---|---|---|
| 1 | `internal/infrastructure/database/sqlite/store.go:979-1017` | `INSERT OR IGNORE` → `INSERT INTO hanzi_data(...) VALUES(...) ON CONFLICT(char) DO UPDATE SET <白名单列>`；白名单显式声明为包级切片常量，**不在字符串里内联** |
| 2 | 同文件 `seedHanziData` | 增加差集删除：维护「本轮键集」，对不在其中的既有行 `DELETE FROM hanzi_data WHERE char NOT IN (...)`（分批 500，避免超长 SQL）；先比对 `data_meta` 的 `materials.hanzi.checksum`，未变则**整段跳过**（避免每次启动全表扫描） |
| 3 | 同文件 | `data_meta` 写入 `materials.hanzi.checksum` / `materials.hanzi.version`（KV 表，不新增列） |
| 4 | 同文件 `createTables` | `data_meta` 无需改结构；确认索引覆盖新过滤维度 |
| 5 | 新增 `store_seed_hanzi_test.go` | 守护测试（见 TDD 清单） |

**TDD（先红后绿）**

- `TestSeedHanziData_字段更新可传导`：灌入 A 字 `positive_score=10` → 改源为 50 → 重灌 → SQL 读回 **50**（**当前必红**）。
- `TestSeedHanziData_删字可删除`：灌 A、B → 源只留 A → 重灌 → B 行消失。
- `TestSeedHanziData_幂等`：同输入连续灌两次 → 行数与内容逐字段一致。
- `TestSeedHanziData_受控列白名单`：新增列未进白名单时**不得**被更新（守护「静默不更新」风险）。
- `TestSeedHanziData_差集删除分批`：>1000 字的删除集合正确。

**回归影响预判**：`queryViaSQL`（`adapters.go:538-603`）此前可能已「依赖」陈旧 SQL 行做错误过滤；改 upsert 后
`SearchHanziByFilter` 结果集可能变化 → **必须**跑 e2e + golden 对比，若有差异先判定哪侧是真值。

### P-1.4　checksum 门控 + gender 行为变更定档（ADR-014）

**问题**：① `namer.json` `version="1.0"` 静态 → 按版本 diff 永不触发；② `normalizeGender("")` 返回 `""`
（`namer_loader.go:152`），6266 个无 gender 字在 `adapters.go:595` 性别筛选下被整批剔除；
改为 `neutral` 会**扩大候选池** → 排名漂移。

**改动清单**

| # | 文件 | 改动 |
|---|---|---|
| 1 | 新增 `internal/materials/checksum/checksum.go` | `File(path) (string, error)`：sha256；快速路径 `size+mtime` 命中即复用（避免 26MB 级重复计算） |
| 2 | `internal/infrastructure/data/dataloader.go` | `Init` 计算各物料 checksum → 与 `data_meta` 比对 → 未变则跳过该物料重灌（**热更新闭环的地基**，ADR-006 复用） |
| 3 | `internal/domain/hanzi/namer_loader.go:152` `normalizeGender` | 增加 `case "": return "neutral"` —— **同时必须**：加特性开关 `NamerGenderNeutralDefault`（默认 on），便于出现漂移时快速回退 |
| 4 | 新增 `normalize_gender_test.go` | 表驱动：`男→male`/`女→female`/`""→neutral`/`null→neutral`/未知→neutral+日志 |
| 5 | 新增 golden 快照设施 | 见 §六 |

**TDD**

- `TestChecksum_改1字节即变`：改源文件 1 字节 → checksum 变更。
- `TestChecksum_快速路径一致`：命中/未命中 `size+mtime` 快速路径时结果相同。
- `Test门控_未变更跳过重灌`：mtime/size 不变 → 日志断言「跳过」。
- `Test门控_变更触发重灌`：内容变更 → 触发重灌且 `data_meta` 更新。
- `TestGender_空值归一`：`normalizeGender("")=="neutral"`（**行为变更，golden 必须同步更新并留档**）。

**留档要求**：gender 语义变更属**行为变更**，须在 `CHANGELOG.md` 标注，并记录变更前后
固定生辰 Top10 排名 diff（供 §五 P0 的评分回归对照）。
