# 入库源清单与物料边界

> 梳理日期：2026-10-26
> 权威定义：`backend/internal/materials/schema`（`Definitions[].Source` / `Definitions[].Files`）
> 运行期真源：SQLite（`materials import` 烘焙一次，运行期不再读 JSON）

## 一、结论

`data/` 下只有 **33 个唯一源文件**需要进入 SQLite，对应 12 类物料。
其余文件要么已合并进 `namer.json`，要么只服务离线生成/统计，**不进入运行期入库清单**。

清单不再依赖目录扫描：`schema.Definitions` 是唯一真源，`classicsSourceFiles`
由 `schema.ClassicsFiles` 派生。目录中多出的 JSON 不会被误导入，清单漏登记
会被守护测试拦截。

## 四、校验与运维

```bash
# 打印清单（物料 → 源文件，含存在性）
./namer materials manifest --data ./data

# 部署前校验：必需源文件缺失即非 0 退出
./namer materials manifest --data ./data --check

# CI 机器可读输出
./namer materials manifest --data ./data --check --json
```

导入仍统一走：

```bash
./namer materials import --data ./data --db ./namer.db
./namer materials status --db ./namer.db
```

## 五、维护规则

1. 新增物料：只在 `schema.Definitions` 登记一次（单文件 `Source`，多文件 `Files`），
   同时在 `classicsFileCategory`（仅经典）登记分类。
2. 新增经典文件：同时更新 `schema.ClassicsFiles` 与 `classicsFileCategory`；
   `store_classics_manifest_test.go` 会做双向校验。
3. 不再被运行时消费的文件：移入 `data/raw/`，并同步更新本清单与 `.dockerignore`。
4. 备份/快照（`*.bak`、项目根 `dataYYYYMMDD.zip`）不得放入 `data/` 入库路径。
