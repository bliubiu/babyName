## 二、候选字范围选取策略对比

候选字范围是起名系统的**根基**——选字池的质量直接决定名字质量。各产品在"哪些字可以用于取名"上的策略差异显著。

### 2.1 babyname/fate — 部首+喜用神联合过滤

**核心机制**：`ExcellentTable`（策展字表）+ 部首五行映射

```
// fate/core/ ExcellentEntry 的核心字段
type ExcellentEntry struct {
    Char       string   // 汉字
    Phonetic   string   // 拼音
    Strokes    int      // 笔画数
    Radicals   []string // 部首列表
    Meaning    string   // 含义
    FiveElement string  // 五行属性
}
```

**选取流程**：
1. **部首五行映射** — 每个汉字通过部首映射到五行属性（金木水火土）
2. **喜用神过滤** — 根据八字分析结果，只保留五行属性与喜用神匹配的字
3. **性别分类** — ExcellentEntry 分为 `male`（男名用字）和 `female`（女名用字），各有独立字表
4. **声调约束** — `SyllableConfig` 定义音节数量约束，确保名字的音韵搭配合理性

**特点**：
- 字表经过策展（curated），不是全量字库
- 支持拼音搜索（`ExcellentPhoneticEntry`）
- 有"可选"属性（`Optional`）标记灵活用字
- **弱点**：策展字表规模有限，可能遗漏一些好字

---

### 2.2 美名腾 — 预策展字库 + 多维过滤

**核心机制**：策展字库（2428男字 / 2088女字）+ 六维过滤

**字库来源与规模**：
- 男名策展字库：**2428** 字
- 女名策展字库：**2088** 字
- 总字库：约4500字（与《通用规范汉字表》一级字表3500字+二级字表3000字有交叉）

**选取流程（六度空间起名法的"补缺"阶段）**：

```
输入：用户八字 → 喜用神（如"水、金"）
         ↓
第一层：五行过滤 → 只保留五行属性为水/金的字
         ↓
第二层：音韵过滤 → 检查字的声母、韵母、声调是否与姓氏搭配
         ↓
第三层：生肖过滤 → 检查字的偏旁部首是否为生肖宜用
         ↓
第四层：字义过滤 → 排除消极含义、生僻字、禁用字
         ↓
输出：可用候选字池
```

**特点**：
- 预策展字库是核心壁垒——"什么字可以用"经过专家审核
- 多层过滤是**层层递进**的关系，每层缩小候选池
- 美名腾的字库包含字义五行判定（不仅看部首，还看字的本义）
- **弱点**：字库规模相对固定，更新依赖人工

---

### 2.3 goodname.ai — AI驱动的动态字库

**核心机制**：20+参数输入 + AI模型动态生成

**选取流程**：
1. **用户输入** → 八字五行、生肖、音律美学、文化寓意等20+参数
2. **AI模型分析** → 模型根据参数组合动态确定候选字范围
3. **典籍溯源** → 自动关联200+国学典籍（诗经/楚辞/周易/论语/成语）
4. **智能校验** → 自动规避生僻字、禁用词、名人重名

**特点**：
- 没有固定字库，AI根据上下文动态决定
- 典籍溯源是差异化特色——每个名字都能找到出处
- 支持"指定字筛选"——用户可以锁定特定字，AI围绕该字生成
- **弱点**：AI"黑盒"特性导致可解释性差，用户不知道为什么选了这个字

---

### 2.4 gushi_namer — 纯随机经典抽取

**核心机制**：经典文献全量随机

**选取流程**：
1. **经典库来源** — 诗经、楚辞、唐诗、宋词、乐府诗集、四书五经、成语等
2. **随机抽取** — 从经典中随机选取诗句/成语
3. **截取** — 从诗句中截取2-3字作为名字
4. **无评分/过滤** — 纯随机，不进行任何算法评估

**特点**：
- 每个名字都有经典出处（"翻阅经典，与一个好名字不期而遇"）
- 极简实现（纯前端，无后端）
- **弱点**：随机性导致质量方差极大，可能出现不雅组合

---

### 2.5 如意宝宝起名 — 六维筛选体系

**核心机制**：偏旁+五行+音调+笔画+书写+结构

**选取流程**：
1. **偏旁筛选** — 按部首过滤（与五行关联）
2. **五行筛选** — 匹配喜用神
3. **音调筛选** — 检查声调搭配
4. **笔画筛选** — 控制笔画复杂度
5. **书写筛选** — 避免难以书写的字
6. **结构筛选** — 检查字形结构搭配

**特点**：
- 最接近传统起名"查字典"的方式
- 用户可手动指定每个筛选条件
- **弱点**：筛选维度多但缺乏整体协调，可能过度限制

### 2.6 本项目（起名Name）— 三层体系 + 策展字库

**当前实现**：

| 层级 | 机制 | 文件 |
|------|------|------|
| **命理层** | 八字排盘 → 喜用神 → 五行需求 | `backend/internal/domain/fate/engine.go` |
| **数理层** | 笔画河图数理 + 易卦象 + 三才 | `backend/internal/domain/fate/rater.go` |
| **字象层** | 部首五行映射(14814字) + 字义五行纠正 | `backend/internal/domain/name/` |

**与竞品对比**：

| 维度 | fate | 美名腾 | goodname.ai | 本项目 |
|------|------|--------|-------------|--------|
| 字库来源 | 策展ExcellentTable | 策展字库(4500字) | AI动态 | 三级字表(14814字) + 全量汉字 |
| 五行判定 | 部首映射 | 部首+字义 | AI推断 | 部首映射 + 字义纠正 |
| 性别区分 | ✅ 男/女分表 | ✅ 男/女分表 | ✅ 参数指定 | ⚠️ 有但未充分利用 |

**关键差距**：
1. **缺少预策展字库** — 美名腾有2428/2088字的精选字表，本项目依赖全量字库
2. **性别区分不足** — fate和美名腾都严格区分男名用字/女名用字
3. **字义五行判定** — 本项目有`17-汉字字形五行判定`文档，但实现中字义法的覆盖度不如部首法

## 三、候选名构建算法对比

候选名构建是起名系统的**核心引擎**——如何从候选字库生成高质量的名字组合。

### 3.1 babyname/fate — 组合生成 + 五维评分排序

**生成流程**：

```
候选字池（ExcellentTable）
         ↓
  ┌──────┴──────┐
  │ 姓氏固定     │
  │ 名1 字A     │
  │ 名2 字B     │
  └──────┬──────┘
         ↓
  组合生成（Cartesian Product）
  → 所有可能的 [姓+A+B] 组合
         ↓
  五维评分排序
  → Cultural Impressions 20%
  → Five Elements 25%
  → Zodiac 10%
  → Numerology 25%
  → Sound/Rhythm 20%
         ↓
  Top-N 输出
```

**评分变体**：
- `ExcellentEntryVariantLucky` — "Lucky"评分变体（基础分）
- `ExcellentEntryVariantLuckyAdverb` — "Lucky Adverb"变体（带副词修饰的幸运分）
- `ExcellentEntryVariantNatural` — "Natural"变体（自然流畅分）

**特点**：
- 笛卡尔积全组合 → 确保不遗漏任何可能
- 五维评分加权排序 → 综合考虑多个维度
- 异步生成 → 支持大规模组合的后台计算
- **弱点**：组合数量可能爆炸（候选池N个字 → N²组合），需要限制

---

### 3.2 美名腾 — 三层流水线生成

**生成流程**：

```
第一层：初步筛选（生成阶段）
  八字喜用神 → 五行过滤 → 生肖过滤 → 字义过滤
  → 输出：可用候选字池（约200-500字）
         ↓
第二层：三才五格评分（筛选阶段）
  从候选池中选取字组合
  → 计算天格/人格/地格/外格/总格
  → 三才配置是否相生
  → 吉数筛选（只保留吉数配置）
         ↓
第三层：后置过滤（优化阶段）
  → 音韵和谐度检查（平仄交替、声韵协调）
  → 字形结构检查（笔画疏密、结构搭配）
  → 谐音审查（排除不雅谐音）
  → 名字数据库比对（避免过度重名）
         ↓
  Top-N 输出
```

**特点**：
- **三层递进**是核心优势——每层逐步缩小范围，确保质量
- 三才五格是传统起名的核心算法，竞品基本都有
- 后置过滤是"安全网"——确保最终输出的名字没有明显问题
- **弱点**：三层流水线可能导致候选名数量过少

---

### 3.3 goodname.ai — AI生成 + 多维约束

**生成流程**：

```
用户输入（20+参数）
  → 八字五行 + 生肖 + 音律美学 + 文化寓意 + 姓氏渊源
         ↓
AI模型分析
  → 理解用户意图
  → 确定名字风格（古典/现代/文雅/大气）
  → 动态选择字库范围
         ↓
生成候选名
  → AI直接生成完整名字（不是字组合）
  → 每个名字附带典籍出处
         ↓
智能校验
  → 自动规避生僻字
  → 排除禁用词
  → 检查名人重名
         ↓
  Top-N 输出（1秒内完成）
```

**特点**：
- AI直接生成完整名字，不是字组合 → 效率高
- 典籍溯源是差异化特色 → 每个名字都有文化出处
- 20+参数输入 → 个性化程度高
- **弱点**：AI"黑盒"→ 可解释性差，用户不知道为什么推荐这个名字

---

### 3.4 gushi_namer — 纯随机经典截取

**生成流程**：

```
经典文献库（诗经/楚辞/唐诗/宋词/乐府/四书五经/成语）
         ↓
随机选取一句诗/成语
         ↓
从诗句中截取2-3字作为名字
         ↓
直接输出（无评分/排序）
```

**特点**：
- 每个名字都有经典出处 → 文化底蕴强
- 极简实现（纯前端）→ 部署简单
- **弱点**：纯随机 → 质量方差极大，可能截取不雅组合

---

### 3.5 如意宝宝起名 — 多维约束生成

**生成流程**：

```
用户指定筛选条件
  → 五行/偏旁/音调/笔画/书写/结构
         ↓
从全量字库中筛选符合条件的字
         ↓
组合生成（笛卡尔积）
         ↓
按条件过滤组合
         ↓
输出候选名
```

**特点**：
- 用户控制力强 → 可精确指定每个筛选条件
- 筛选维度多 → 可以实现非常精确的控制
- **弱点**：维度过多可能导致候选名过少，需要用户手动调整

### 3.6 本项目（起名Name）— DDD分层生成 + 八维评分

**当前实现**：

```
入口：GenerateUnified()
         ↓
  ┌──────┴──────┐
  │ buildCandidates()  │  ← 候选字池构建
  │ ├ 部首五行过滤     │
  │ ├ 生肖喜忌过滤     │
  │ ├ 音韵初步筛选     │
  │ └ 笔画约束         │
  └──────┬──────┘
         ↓
  ┌──────┴──────┐
  │ generateDoubleNames() │  ← 双名生成
  │ generateSingleNames() │  ← 单名生成
  └──────┬──────┘
         ↓
  ┌──────┴──────┐
  │ evalPair()          │  ← 评估函数
  │ ├ 音韵搭配评估      │
  │ ├ 三才五格计算      │
  │ ├ 字义组合评估      │
  │ └ 生肖适配评估      │
  └──────┬──────┘
         ↓
  八维加权评分
  → WuxingRater     24%
  → WenHuaRater     14%
  → YinYunRater     14%
  → ShengXiaoRater  11%
  → SancaiRater      8%
  → NoveltyRater    14%
  → BigramRater      9%
  → FrequencyRater   6%
         ↓
  按总分降序排序 → Top-N 输出
```

**与竞品对比**：

| 维度 | fate | 美名腾 | goodname.ai | 本项目 |
|------|------|--------|-------------|--------|
| 生成方式 | 笛卡尔积全组合 | 三层流水线 | AI直接生成 | 笛卡尔积+evalPair |
| 评分维度 | 5维 | 6维(六度空间) | 20+参数 | 8维 |
| 排序机制 | 加权评分降序 | 三才五格筛选 | AI置信度 | 加权评分降序 |
| 异步支持 | ✅ | 未知 | ✅(1秒) | ✅(goroutine) |
| 候选池排序 | 无 | 三才五格预筛 | 无 | ✅(FrequencyRater) |

**关键优势**：
1. **八维评分** — 维度最多（fate5维、美名腾6维），覆盖全面
2. **候选池排序** — FrequencyRater 参与候选字预排序，优先使用高频字
3. **DDD架构** — 领域层/应用层/基础设施层分离，代码质量优于竞品

**关键差距**：
1. **缺少三才五格预筛** — 美名腾在生成阶段就排除不吉数理配置，本项目在评分阶段才计算
2. **字库策展不足** — 美名腾有2428/2088字精选字表，本项目依赖全量字库
3. **后置过滤不完善** — 美名腾有谐音审查、字形检查等后置过滤，本项目缺少

## 四、名字分析与解读对比

名字生成后的分析与解读是用户体验的关键——用户需要理解"这个名字好在哪里"。

### 4.1 babyname/fate — 五维雷达图 + 卦象解读

**分析维度**：

| 维度 | 权重 | 解读内容 |
|------|------|---------|
| 文化印象 | 20% | 名字的文化内涵、经典出处 |
| 五行八字 | 25% | 五行属性匹配度、八字喜用神 |
| 生肖 | 10% | 生肖宜忌用字 |
| 五格数理 | 25% | 天格/人格/地格/外格/总格吉凶 |
| 音韵 | 20% | 声调搭配、韵母和谐 |

**呈现方式**：
- 五维雷达图（直观展示各维度得分）
- 卦象解读（易经64卦）
- 喜用神分析（平衡用神法+格局用神法）

**特点**：
- 雷达图直观 → 用户一眼看出名字的强项和弱项
- 卦象解读是差异化特色 → 传统文化深度
- **弱点**：缺少文字解读（只有图表，没有"为什么好"的解释）

---

### 4.2 美名腾 — 六度空间深度解读

**分析维度**：

| 维度 | 解读内容 |
|------|---------|
| 八字五行补缺 | 名字五行如何弥补八字缺失 |
| 生肖适配 | 生肖宜用字形/偏旁分析 |
| 音韵和谐 | 平仄交替、声韵协调分析 |

| 字形匀称 | 结构搭配、书写美观度 |
| 五格数理 | 五格吉数、三才相生 |

**呈现方式**：
- 六维雷达图
- 每个维度的文字解读（详细解释）
- 名字评分（100分制）
- 诗词典故出处（诗经/楚辞/周易/论语/成语）

**特点**：
- **最全面的解读** — 每个维度都有详细文字说明
- 诗词典故是核心特色 → 文化底蕴深厚
- **弱点**：信息过载，用户可能看不完

## 八、结论

### 本项目的核心优势

1. **八维评分体系** — 竞品中维度最多，覆盖最全面
2. **人名频率数据** — 独家特色，竞品没有
3. **易经卦象解读** — 差异化特色，仅fate也有
4. **功能覆盖最全** — 收藏/对比/重名率/图片导出/历史记录
5. **DDD+TDD架构** — 代码质量最高
6. **离线运行** — 隐私保护最强

### 本项目的核心差距

1. **策展字库不足** — 缺少精选字表，名字质量下限较低
2. **谐音审查不完善** — 可能产生不雅谐音
3. **文字解读不足** — 用户不知道"为什么好"
4. **AI能力缺失** — 追赶goodname.ai的AI生成+AI解读
5. **生成速度较慢** — 笛卡尔积全组合导致性能问题

### 战略定位建议

**"最懂传统文化的开源起名工具"**

- **开源** — 对标fate（2.4k⭐），目标成为开源圈第一
- **传统文化** — 易经卦象+诗词典故，差异化特色
- **人名频率** — 独家数据维度，竞品没有
- **功能全面** — 收藏/对比/重名率/图片导出，体验最好
