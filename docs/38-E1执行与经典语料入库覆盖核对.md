## 1. E1：kangxi_strokes 按 hanzi_data 字符集裁剪 —— 已执行

### 1.1 时序安全性结论（先于裁剪确认）
- 物料拓扑：`KangxiMaterial`(`kangxi`, 无依赖) → `NamerMaterial`(`namer`, `DependsOn: [kangxi]`)。即 **kangxi 先于 namer 落库**。
- `importNamer` 的康熙笔画来自 `opt.deps.kangxi`（**从 CSV 源文件直接预解析注入**，不经 `kangxi_strokes` 表回读，见 `store_materials_import.go:99-101, 469-479`）。
- `kangxi_strokes` 表的唯一消费方是 `LoadKangxiStrokesFromDB` → 内存 map → `GetKangxiStrokes(char)`（**缺失返回 0，优雅降级**）。
- 因此裁剪该表**不影响任何导入或运行期正确性**：候选池只在字库内选字，孤儿行永远查不到；裁剪后缺失字返回 0，与裁剪前行为一致。
- 安全锚点：裁剪放在 `Import()` 末尾（`syncNameFreqTier` 同位置），此时两表均已全量落库，裁剪安全。

### 2.3 口径说明
- **extracts(字集)** = 起名用字集，运行期 `FindPoetryByChars`/`GetBigramScore` 据其判出典与搭配分 → **缺此类即无出典加分**。
- **poem_entries(索引)** = 出典展示索引（前端展示「出自《X》」用）→ 进了索引仅能在结果页展示出处，**不影响评分**。
- **根因**（docs/37 已定位）：`internal/domain/classics/classic_loader.go` 的 `LoadFromJSON` 字集 dispatch 只注册了 `loadShiJing/loadChuCi/loadGuWen/loadShiCi` + 通用 `loadClassicFromJSON`，**没有 `loadYuanQu/loadYueFu/loadCiFu`**；而 poem_entries 走的是另一条（按文件枚举）写入路径，故二者不一致。
- yijing 按设计走独立 `yijing_hexagrams` 表（卦象不参与字集），**不计入缺口**。
- `sanzijing-traditional.json` 与 `sanzijing-new.json` 是同一蒙学的简/繁变体，仅繁体未进字集，属次要重复，可后续合并或忽略。
