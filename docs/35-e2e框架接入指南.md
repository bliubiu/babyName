# 35 - tester-army/e2e 框架接入指南（测试起名核心业务）

> 目标：用 <https://github.com/tester-army/e2e> 对起名核心业务做浏览器级 / 接口级 E2E 测试。
> 该框架是「Agentic E2E」：可用 `agent.act('自然语言目标')` 驱动浏览器，也可用 `expect(locator)` 做确定性断言（**零模型调用**）。

## 1. 框架认知：它是什么、适合测什么

| 维度 | 说明 |
|---|---|
| 形态 | Node.js/TypeScript SDK + Runner + CLI，npm 包名 `e2e`（本机锁定 `0.21.2`） |
| 引擎 | `@e2e-dev/web`（Chromium/Firefox/WebKit，基于 Playwright）、`@e2e-dev/mobile`（iOS/Android） |
| 核心玩法 | `agent.act('自然语言目标')` 驱动页面；`agent.assert()` 语义断言；`expect(locator)` 确定性断言 |
| 省钱机制 | agent 步骤会被**录制并重放**：应用不变时后续运行不调模型；**纯 `expect` 断言完全不需要模型** |
| 模型 | BYO（订阅 / API Key / 本地模型均可）；纯契约 / 纯 locator 用例不需要任何模型 |
| 成熟度 | 0.x，API 仍可能变动 → **务必锁定版本**；Apache-2.0 |

与本项目现有测试体系的关系（**互补而非替代**）：

- `tools/e2e_check`（Go，18 项巡检）：**API 级**冒烟/巡检，跑在 CI。
- tester-army/e2e：**浏览器 UI 级** + **接口契约级**，覆盖"用户真实操作路径"——表单填写→生成→结果页渲染，以及接口契约回归（性别回显、姓氏前缀等）。

## 2. 前置条件（本机已满足）

- Node 22+（本机 22.23.2 ✓）
- pnpm（项目禁用 npm 管理依赖）
- 后端可构建 / 可启动：`go run ./backend/cmd/server`（需 GOPROXY 或离线缓存）
- 前端：`cd frontend && pnpm install && pnpm dev`（Next.js 16 dev server）

## 3. 接入步骤（已实际落地）

### 3.1 依赖

在 `frontend/` 目录下：

```bash
pnpm add -D e2e@0.21.2 @e2e-dev/web@0.15.2
```

> 离线文档随包分发：`node_modules/e2e/docs/`；0.x 阶段配置字段可能调整，以该文档为准。
> 浏览器二进制缺失时用国内镜像装（见 §6.9），不要走官方 CDN（国内 ECONNRESET）。

### 3.2 配置文件

- `frontend/e2e.config.ts` —— web 引擎（UI 用例用）：
  ```ts
  import type { E2EConfig } from 'e2e';
  import { web } from '@e2e-dev/web';
  export default {
    targets: [{ name: 'web', engine: web({ browser: 'chromium' }), app: { url: 'http://127.0.0.1:3000' } }],
    timeout: 180000, actionTimeout: 30000, assertionTimeout: 10000, workers: 1,
  } satisfies E2EConfig;
  ```
- `frontend/e2e.config.api.ts` —— 无引擎（接口契约用例用，**不走浏览器**）：
  ```ts
  import type { E2EConfig } from 'e2e';
  export default {
    targets: [{ name: 'api', platform: 'api' }],
    timeout: 60000, workers: 1,
  } satisfies E2EConfig;
  ```

### 3.3 测试文件（已实际跑通，纯确定性、零模型）

两份都在 `frontend/tests/`：

- `naming-api.e2e.ts` —— 接口契约。直接用 `fetch` 打 `127.0.0.1:8080`，断言 `POST /api/v1/names/generate` 返回 200、候选名非空、每个 `full_name` 以请求姓氏开头、`gender==='male'`。**零浏览器、零模型**，约 2s 跑完。
- `naming-ui.e2e.ts` —— UI 主链路。用 `screen.getByPlaceholder/getByRole/getByText` 填表（姓氏"李"）、点"开始取名"，等结果页出现"李"开头候选名。**未配置模型，纯 locator 断言**。

```ts
// frontend/tests/naming-ui.e2e.ts（核心片段）
import { test } from '@e2e-dev/web';
import { expect } from 'e2e';

test('起名主链路：首页填表 → 生成 → 结果页出现候选名', async ({ app, screen }) => {
  await app.open('/');
  await expect(screen.getByRole('heading', { name: '宝宝起名' })).toBeVisible();
  const surname = screen.getByPlaceholder('请输入姓氏');
  await surname.fill('李');
  await screen.getByRole('button', { name: '开始取名' }).click();
  // e2e 的 App 无 waitForURL；改为等结果页真实内容（"李"开头候选名文本）
  const firstCandidate = screen.getByText(/^李/).first();
  await expect(firstCandidate).toBeVisible({ timeout: 90000 });
});
```

> 注意：App 接口只有 `open/restart/clearState/back/screenshot`，**没有 `waitForURL`**；结果页等待必须用 `expect(locator).toBeVisible()`。

## 4. 实际跑通记录（★ 关键步骤）

> 这是本机实测可用的完整链路。**第 0 步是血泪教训**：后端若没导入物料，`hanzi_data` 为空，生成接口会全部返回 400（零候选名），UI 与接口用例必然失败——与异步/并发无关。

### 0. 初始化数据库（★ 必做，否则全 400）

后端启动时会读 `./namer.db`（相对工作目录）。若库为空（`sqlite: hanzi_data 为空`），引擎回落到"内置降级数据"，生成候选池恒空 → 每个起名请求 400。

```bash
cd <项目根>                       # 工作目录 = 项目根（data/ 与 namer.db 都相对它）
go run ./backend/cmd/materials import --data ./data --db ./namer.db
# 期望：写入 12 项（kangxi/namer/name_frequency/.../classics 等），耗时数秒
```

> 判定库是否已就绪：`go run ./backend/cmd/materials status --db ./namer.db` 看 `hanzi_data` 行数（应有 ~8105）。
> 项目根的 `namer.db` 曾被实例跑成 4KB 空库；导入后变 ~23MB、行数正常，接口即恢复。

### 1. 起后端（工作目录 = 项目根）

```bash
cd <项目根>
go run ./backend/cmd/server       # 监听 127.0.0.1:8080；db=./namer.db，dataDir=./data
```

离线构建（无网络）：用预编译二进制亦可，`backend/.workbuddy/tmp/namer-server.exe`（GOPROXY=off 编译产物）。

### 2. 起前端（dev，直连后端）

dev 下 Next 不托管 API 路由，需显式指向后端（CORS 白名单已放行 `127.0.0.1:3000`）：

```bash
cd frontend
NEXT_PUBLIC_API_URL=http://127.0.0.1:8080/api pnpm dev   # 监听 127.0.0.1:3000
```

### 3. 跑测试

```bash
cd frontend
# 接口契约（无浏览器，快）：必须用 --config 指定 api 配置
pnpm exec e2e run --config e2e.config.api.ts tests/naming-api.e2e.ts

# UI 主链路（Playwright Chromium）：默认 e2e.config.ts
pnpm exec e2e run tests/naming-ui.e2e.ts
```

实测结果：

```
✓ api  tests/naming-api.e2e.ts (1 test)   ~2s     # 零浏览器、零模型
✓ web  tests/naming-ui.e2e.ts  (1 test)   ~26s    # Playwright Chromium
```

## 6. 本项目专属注意事项（踩坑映射）

1. **用 `127.0.0.1` 不用 `localhost`**：本机 localhost 解析 IPv6 `::1`，历史上有稳定 ~2s 假延迟与连通性问题。
2. **★ 空库即全 400**：`materials import` 是跑通前提（见 §4.0）。后端日志关键字：`sqlite: hanzi_data 为空` / `物料库缺失必需物料 6 项` / `SQLite 字库为空...回退 Go 端全表过滤` / `Generate: name generation failed`。
3. **异步生成 ≠ 并发 bug**：此前曾怀疑 `Progress()` 与 `Wait()` 并发不安全，但 `sessionImpl.Progress()` 只原子读 `stage/percentX`，引擎本身线程安全。UI 主链路失败的真实原因是空库导致零候选名，与同步/异步无关。
4. **代理坑**：本机环境 127.0.0.1 请求曾走代理返回假 502（curl 需 `--noproxy '*'`）。浏览器引擎若读系统代理，需对 `127.0.0.1` 配 no_proxy。
5. **生成接口耗时**：`/names/generate` 秒级返回。结果页断言 `timeout ≥ 30s`（UI 用例给到 90s）。
6. **编码**：测试脚本一律 UTF-8 无 BOM；中文断言直接写中文。
7. **版本锁定**：框架 0.x，`pnpm add -D e2e@<精确版本>` 锁死，升级时读 `node_modules/e2e/docs`。
8. **遥测**：CLI 默认发匿名遥测，介意则 `E2E_TELEMETRY_DISABLED=1`。
9. **Playwright 浏览器**：国内下载走 `PLAYWRIGHT_DOWNLOAD_HOST=https://cdn.npmmirror.com/binaries/playwright`，装 `chromium_headless_shell`；**不要**设 `PLAYWRIGHT_BROWSERS_PATH=0`（会改浏览器查找目录导致找不到已装二进制、进而 hang 在下载）。
10. **与 e2e_check 的分工**：接口契约回归（错误码、性别回填、诗词出处）继续由 Go 集成测试 + e2e_check 把守；UI E2E 只管"用户路径通不通"。

## 7. 选型小结

| 需求 | 用什么 |
|---|---|
| 接口契约/巡检（CI 门禁） | 既有 `tools/e2e_check -strict` |
| 用户操作路径（表单→生成→结果页） | tester-army/e2e（web 引擎 + expect） |
| 接口契约（零浏览器快速回归） | tester-army/e2e（api 配置 + fetch + expect） |
| 单元/集成（TDD） | Go test / pnpm test（前端 36 例） |
