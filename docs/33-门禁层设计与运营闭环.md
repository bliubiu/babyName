## 一、结论

- 几乎所有线上产品都设「内容门禁/黑名单」层；生成式/推荐式产品（含起名）必须做**输出侧门禁**——
  你为自己产出的内容负责，违规成本高于仅过滤用户输入。
- 成熟范式归纳为四件套：**① 分层匹配引擎 ② 可独立发布/可回滚的版本化词表 ③ 白名单/豁免 ④ 指标与人审运营闭环**。

## 二、分层（纵深防御 + 分级，本项目已是此形态）

| 层 | 作用 | 业界做法 | 本项目对应 |
|---|---|---|---|
| L1 词元级 | 廉价高精度，前置剪枝 | 黑名单 trie 剔除 | `IsNonNamingChar`（naming_quality 2990 字，候选池阶段） |
| L2 组合/规则级 | 上下文/组合风险 | 禁用组合/正则/命名实体（机关、地名、历史人物） | `IsBadCombo`(962)/`IsHistoricalFigureCombo`/`PairBlacklist` |
| L3 语音/形近级 | 防绕过 | 拼音/繁简/全半角/leetspeak/谐音/近音/形近字归一后再匹配 | `CheckBadPinyinCombo`/`CheckAllBadHomophones`（stripTone+连读含姓氏） |
| L4 模型/风险分级 | 兜底、可解释 | 分类器打分→pass/warn/block，borderline 人审 | `AssessNameRisks`(pass/warn/fail) |
| L5 合规/法务 | 红线 | 政治/机关/宗教/品牌/时政法务词表 | ✅ 独立物料 `compliance_redline`（M2，机关单位/争议地名/负面历史人物） |

原则：**廉价检查前置收敛空间，昂贵检查后置收口**（本项目字级先剔、谐音/风险后查）。

## 四、匹配技术

- **归一化前置**：大小写/繁简/全半角/去噪/拼音去调后再匹配（`stripTone`）。
- **多模式匹配**：长词/多模式用 Aho-Corasick/DFA trie（O(n)）；本项目多为双字，`map` 足够，词表扩到词组时上 trie。
- **谐音/近音/形近**：拼音归一 + 近音/形近表。

## 五、分级处置（非二元）

- 动作集：`block(硬删) / downrank(降权) / warn(标注) / 人审 / allow`。
- 本项目 `pass/warn/fail` 已是分级；建议把 `warn` 接入复审队列闭环，`fail` 给可解释命中原因（e2e 已展示 gateHits）。

## 六、工程与运营（最难是运营，非代码）

1. **表与代码分离、独立发布**（改词不发版）——已做到（JSON 外置热载）。
2. **版本化 + 热更新 + 回滚**——`data_meta` checksum + `materials import` + 原子 swap
   （ADR-006/008/011/014；**门控以 checksum 为准**）。
3. **审计追溯**：谁/何时/为何加词；命中日志脱敏（M3 已落地）——`fate.RecordGateHit` 结构化埋点
   （`CheckBadPinyinCombo` / `AssessNameRisks` 命中点），`gateaudit.Install()` sink 落日志，
   `tools/gate_audit` 出「命中审计快照」。
4. **灰度发布**新表：小流量→观察命中/误报→全量——M7 落地「按物料整体」
   `stage→observe→promote|abort`：两态 lock（`active`/`staging`）+ `data/staging/` +
   append-only `data/release.jsonl`（可审计、可整物料回滚）。✅
5. **指标闭环**：命中率、误报率、漏报率(抽样)、命中延迟、复审时长——M4 落地「本地可算」部分
   （命中率/命中分布 + `/metrics` 端点）；M6 接入复审闭环真实数据源（误报率/漏报率代理/复审时长）。
6. **误伤治理/申诉**：白名单豁免 + 误报监控 + 人审回流——M6 落地 `gate_review` 状态机 + 收藏回流 + `gate_patch`。
7. **评测/回归**：每次改表跑「应命中+不命中」case + golden 回归（`naming_quality_test.go`「优质组合不误伤」即此范式）。

## 九、回流闭环（bad-case → 人审 → 沉淀回表）

**天然钩子**：收藏(favorite)是隐式正反馈（已写 `curated_names`）——**被收藏的名字大概率是好的**。

1. **触发**：命中 `warn`/`fail`；**「warn 却仍被收藏」= 误报候选（高价值）**。
2. **评审队列**：新增 `gate_review(pending)` → 人审三态 `confirmed(违规)/false_positive(误报)/border(边界)`；命中侧在 `CheckBadPinyinCombo`/`AssessNameRisks` 判定点记录 `名字+层级+命中值`（**脱敏**：名字是产物无 PII，但用户画像/note 脱敏）。
3. **沉淀回表**：`confirmed→增补 forbidden/gate`；`false_positive→进 allowlist（白名单优先于黑名单）`；`border→调阈值/权重`。写成 **append-only `gate_patch.jsonl`** → 走 ADR-008 `materials import` 版本化合入（独立发布/可回滚/可审计）。
4. **度量闭环**：命中率、误报率、漏报率(抽样)、复审时长、**回流到表时长**。

**最小落地路径**：`gate_review` 表/状态机 + 命中埋点 + 收藏触发正样本 → `gate_patch.jsonl` → 复用车载 `materials import` 合入 `forbidden/gate/allowlist`，全部版本化、灰度、可回滚。

### M1 显式 allowlist 物料（2026.10.16.3）

- **物料**：新增 `allowlist`（`allowlist.json`，`Required:false` 可选物料），落库 `allowlist(entry PK, kind)`，

- **匹配优先级**：`allow > deny` —— `IsNonNamingChar`（字级）、`IsBadCombo`、`IsHistoricalFigureCombo`（组合级）
  在判定入口先查白名单，命中即豁免；祈福组合 `IsBlessingCombo` 取「内置 `blessingCombos` ∪ 物料 blessing」并集。
- **装载**：库路径 `loadAllowlistFromDB` → `fate.SetAllowlist`（接入 `LoadMaterialsFromDB`）；

- **零回归**：动态集合为空时行为与既有完全一致；`allowlist` 不计入 `materialNames()` 必需物料清单，
  不影响 `VerifyMaterialsFromDB` 的 fail-fast。
- **数据**：`backend/data/allowlist.json` 种子含 9 条祈福组合（去病/弃疾/除疾/愈病/去疾/除病/愈疾/安恙/康宁），

### M2 L5 合规红线独立物料（2026.10.16.4）

- **匹配**：`IsComplianceRedline(fullName)` —— 全名精确、名部（去姓氏首字）精确、

### M3 命中审计埋点（2026.10.16.5）

- **埋点原语**：新增 `fate/audit.go`——事件 `GateHit`（来源 / 层级 / 类别 / 等级 / 名字 / 命中值 / 说明）
  与 `RecordGateHit`；`GateAuditTotal` / `GateAuditCounts` / `GateAuditRecent` / `ResetGateAudit` 读取与重置，
  `SetGateAuditSink` / `SetGateAuditThrottle` 配置。
- **热路径保护**：采用「全量计数 + 详情节流」——计数始终精确累加；详情按
  (层级, 类别, 等级, 命中值) 去重，同一键在节流窗口（默认 1s）内只留一条，环形缓冲封顶 256 条。
  双名 N² 评分高频命中因此不会淹没日志，也不会拖慢生成。
- **脱敏前置**：`RecordGateHit` 入队前对 名字 / 命中值 / 说明 统一掩码——身份证（18 位）、
  邮箱、手机号 → `***`（规则顺序 身份证 → 邮箱 → 手机号，避免短模式吃掉长模式）。名字是产物，
  仍统一过掩码以防调用方误传用户输入。
- **接入点**：`CheckBadPinyinCombo`（评分链路，L3/谐音连读/fail/命中值=谐音词）、
  `AssessNameRisks`（测名体检，`defer` 汇总非通过项，层级由 `riskCategoryLayer` 归类 L0~L4）。

### M8 匹配性能：Aho-Corasick 多模式匹配（2026.10.16.10）

- **背景**：门禁词组匹配中 `IsBadCombo`/`IsHistoricalFigureCombo`/`IsBlessingCombo` 已是 O(1) map 查，
  唯一线性热点是合规红线的 `matchAnyEntity`——对每条红线做 `strings.Contains(fullName, entry)`，
  即 **O(模式数 × 文本长)**，随物料扩增退化。
- **实现**：新增 `fate/actrie.go`——纯 Go、无第三方依赖的 Aho-Corasick 自动机：
  `NewACTrie(patterns)`（去重、BFS 构建 fail 指针并把 fail 链模式并入 outputs）、
  `MatchAny`（短路）/`FindAll`（去重、首命序）/`PatternCount`；构建后只读、可并发。
- **接入**：`compliance_redline.go` 的三套动态红线集合与内置兜底 `forbiddenEntities` 各建一个自动机
  （`newRedlineTrie` 跳过单字条目，保持原语义）；`SetComplianceRedline` 重建三套 trie，
  `IsComplianceRedline` 经 trie 走查（白名单豁免语义不变）。
- **等价性**：全量 `fate` 既有合规红线测试未改动即通过（全名子串命中、单字忽略、白名单优先，均等价）。
- **性能对比**（5000 条双字词表 × 3 字名字，`-benchmem`）：

  | 实现 | ns/op | B/op | allocs/op |
  |---|---|---|---|
  | 线性 `strings.Contains` | 142604 | 2172 | 48 |
  | Aho-Corasick trie | 69.81 | 0 | 0 |

  即 **约 2000× 提速、零分配**，且随词表增大差距进一步拉大。
- **测试**：`fate/actrie_test.go`（MatchAny/FindAll/去重空模式/中文组合/边界/单字跳过/`matchAnyEntity` 边界）
  + 性能对比 benchmark；`actrie.go` 与 `compliance_redline.go` 新增/改动函数覆盖率 100%。

## 十二、灰度发布设计（M7：按物料整体 staging + 观察窗口 + 回滚）

> 状态：**已落地**（ADR-015，2026.10.16.11）；切分粒度 = **物料整体**（`naming_gate` /
> `forbidden_combos` / `allowlist` / `compliance_redline` 各一份独立版本）。

### 12.1 为什么按物料整体

- 单机部署、短文本（2~3 字）、单物料词表规模有限（千级），**无多实例流量分流需求**；
- 黑/白名单天然可分别灰度（`allowlist` 与 `naming_gate`/`forbidden_combos` 各自独立版本）；
- 状态与实现复杂度最低：一个物料 = 一个 active 版本 + 至多一个 staging 候选；
- 明确**不做**：kind 级切分、条目百分比分流、按请求比例放量（留作多实例演进，另立 ADR）。

### 12.2 状态与产物

```
materials.lock
  active   : { material -> 产物 sha256 }   # 当前生效（即现有 entries）
  staging  : { material -> 产物 sha256 }   # 候选（可选，缺省视为无候选 / 单态旧格式）
data/staging/<material>.json               # 候选物料文件（不参与运行时装载）
data/release.jsonl                         # append-only：时间/物料/动作/新·旧指纹/操作者/窗口
```

- **向后兼容**：`lock` 缺 `staging` 字段即按单态旧格式解析（等价「无候选」）。

### 12.3 发布流（三步，显式不自动）

```
① stage    候选落 data/staging/ + 写 lock.staging 指纹
   materials stage   --material allowlist --from <候选.json> [--source <url/note>]
② observe  新旧 diff + 预演报告（新增/移除条目、命中数变化、受影响名字样本）
   materials observe --material allowlist [--limit 20]       # 候选 vs 生效条目差分预演
③ promote  覆盖生效路径 + 更新 lock.active + 记 release.jsonl
   materials promote --material allowlist
   或 abort
   materials abort   --material allowlist                     # 丢弃候选
   materials abort   --material allowlist --to <lock 版本>     # 回退 active 到上一指纹
```

- **观察窗口**：`observe` 给出条目差分预演；窗口内由人观测 `GET /metrics` 的 `gate_*`（命中率/
  误报率/漏报代理/复审时长）与 `gate_review` 人审；窗口期**不自动放量**，由人执行 `promote|abort`。
- **回滚**：`abort --to <版本>` = 以 lock 上一版本产物原地替换 + 重新 `materials import`；
  与 M5 `patch --rollback` 同源，但**粒度到整物料**、以 lock 指纹为真源。

### 12.4 指标与验收

- 灰度的「观察指标」复用 M4/M6：`GET /metrics` 的 `gate_*` + `gate_review` 的误报率/复审时长。
- 验收：`stage → observe → promote` 全流程演练 + `abort --to` 回滚演练（新旧指纹可核对）；
  **明确不验收**流量分流（本设计不含）。

### 12.5 与既有机制的关系

- 复用 M5：`materials.lock`（扩两态）、`gate_patch`/`ApplyToFile`（回滚底层）、`materials import`。
- 与 M6 协同：灰度窗口「是否放量」的决策依据 = M6 复审指标（误报率/漏报代理）。
- 与 ADR-008/011/014 一致：SQLite 为唯一运行时源、以 sha256 指纹门控。
