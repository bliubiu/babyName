# 40 - 物料管线落地审查与优化改造方案

> 状态：方案定稿（2026-10-21）。基于「两路只读源码审查 + 人工抽查证实」：导入管线（`cmd/materials` → `Store.Import`）与运行时装载链路（`server` 启动 → `LoadMaterialsFromDB`）。
> 本文为实施契约：**本次实施范围 = 方案 A（A1–A5）+ B6（全链计时）**；B7–B10 与 C 组列入后续待办，不在本批次落地。

## 一、架构基线

```
data/*.json (15+ 物料, 最大 26MB word.json)
  → cmd/materials import        CLI 入口（6 处 --db 已收口 resolveDBPath）
  → checksum.File sha256        指纹比对 materials_state（ADR-014），未变短路
  → schema.TopoSort             拓扑排序（kangxi → namer → charfreq/bigram → classics）
  → Store.Import                注册表多态分发；每物料：BEGIN IMMEDIATE 单事务
    └ DELETE 全表重建（ADR-011）+ tx.Prepare 预编译逐行 INSERT
  → materials_state 登记（sha256/row_count/version，UPSERT）
  → 收尾（事务外）              syncNameFreqTier / pruneKangxiStrokes

运行期：server → initStore（失败回落内存库）
        → LoadMaterialsFromDB 全量预载内存 map（GetHanzi O(1)，RWMutex）
        → data/*.json 仅 fallback / 离线导入期消费（ADR-008）
```

支撑性 ADR：ADR-008（SQLite 唯一真源）、ADR-011（DELETE+INSERT 全量重建）、ADR-014（sha256 指纹短路）。管线整体质量高（拓扑排序、注册表多态、单事务、指纹短路、跨依赖预注入），本方案是短板修补而非重构。

## 三、本次实施方案（A1–A5 + B6）

### A1 classics 目录指纹

**现状**：`schema.Definition` 仅 `Source string` 单文件；指纹 = `checksum.File(dataDir/Source)`。

**改造**：
1. `schema.Definition` 新增 `Files []string`（相对 dataDir 的多文件清单；空 = 单文件兼容，语义不变）。
2. `Definition` 清单里 classics 定义补全 22 文件 `Files`（以 `store_classics.go` `classicsFileToBook` 键集为基准）；同时在 `import_classics` 内做**双向交叉校验**（Files ⇄ classicsFileToBook），防止未来加文件只改一处。
3. `internal/materials/checksum` 新增 `Files(dir string, rel []string) (string, error)`：按路径稳定排序 → 逐文件 sha256 → 以 `path\0size\0hash` 串接 → 整体再 sha256。
4. `importOne`：`len(def.Files)>0` 时多文件校验 + 目录指纹；任一文件缺失按 Required 口径报错。
5. 兼容迁移：旧库单文件指纹与目录指纹必然不匹配 → 下次导入 classics 全量重灌一次（一次性、可接受，发布说明中注明）。

### A2 失败文件不自愈 → 自动重试

**改造**：`importClassics` 从共用 `runImport` 骨架改为**自带事务**特例化（与 `importCurated` 同形态）：`Begin → DELETE classics 四表 → 逐文件解析/写入（失败文件仅日志+Reason，不阻断）→ 受控登记 → Commit/defer Rollback`。

登记口径：
- 全部文件成功 → 登记目录指纹（短路正常）。
- 有失败文件 → 登记指纹追加 `"/partial"` 后缀（与纯指纹永不相等 → `materialUnchanged` 判 false → **下次导入自动重试**），`Reason` 汇总失败文件清单。

单人手动路径 ≤ `--lenient` 全量重灌；自动路径不再负增长。

### A3 收尾派生事务化

`store_materials_import.go:118-136` 重构为 `runDerivedMaintenance() error`：独立 `BEGIN IMMEDIATE → syncNameFreqTier → pruneKangxiStrokes → COMMIT`，失败返回包裹错误。`ImportReport` 新增 `PartialCommitted bool` 与说明列，CLI 输出提示「物料本体已妥协，建议 --lenient 重建修复派生列」。

### A4 依赖注入硬失败

`resolveImportDeps`（`store_materials_import.go:172-188`）解析失败直接 `return nil, fmt.Errorf("kangxi 笔画 CSV 解析失败: %w", err)`，删除「解析失败留空 map 不阻断」注释与行为——kangxi 是 required 物料，静默继续只会制造 A-3 那类永久 0。

### A5 readyz 真探活

`Store` 新增 `ReadPing() error`：读连接（`mode=ro` 池）执行 `SELECT 1 FROM materials_state LIMIT 1`。`main.go` readyz 改为**优先 ReadPing**，成功后再用内存 map 慢查（保留快速路径语义）；失败则 readyz 反 503。落地前核对 store 读连接字段名与封装层次。

### B6 全链计时

- 装载：`LoadMaterialsFromDB` 每物料步骤 `time.Since` → 日志加 `{"耗时": "12.3ms"}`（沿用现有中文日志风格）。
- 导入：`ImportResult` 新增 `Elapsed string`；`importOne` 计时；CLI 表格与 `--json` 各加耗时列。

## 四、验收标准（TDD，先测后实现）

| 用例 | 断言 |
|---|---|
| T-A1 目录指纹 | 22 文件中任一字节变化 → 指纹变化 → 重灌；全不变 → 短路 |
| T-A2 失败自愈 | 注入 1 个失败文件 → 登记 `"/partial"` 指纹；修复后下次导入重试该文件；全绿后第三次导入短路 |
| T-A3 依赖硬失败 | kangxi CSV 损坏 → Import 立即整体失败；namer 表保持空（无 `kangxi_strokes=0` 的脏行落库） |

| T-A5 ReadPing | 正常库 nil；损坏/被锁库返回 error 且 readyz 收敛 503 |
| 回归 | 既有 12 个 store 测试文件 + `go test ./...` 全绿；`gofmt` 无 diff |

## 五、风险与迁移

1. **一次性全量重灌**：A1 指纹口径切换后首次导入 classics 会重灌（约数秒），幂等性不受影响。
2. **classics 特例化**：脱离 runImport 骨架后需守护测试锁住「失败文件不短路」行为，防止未来回归。
3. **ReadPing 依赖 materials_state 表存在**：该表为库内 always-on 表（`createMaterialTables` 必建），缺表场景已在 `initStore` 内核层兜底（回落内存库，main.go:249-257）。
4. 后续 B/C 里程碑不阻塞本批次；B-7/8/10 需单独 schema 探讨（索引取舍），另立文档。

每步：先测试后实现，步后全量回归。
