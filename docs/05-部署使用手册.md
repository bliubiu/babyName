# 🍼 起名 (Namer) 部署使用手册（Wails v3 桌面端）

> 状态：✅ 与 master 同步（Wails v3.0.0 桌面端 + ADR-010 单库交付）。
> 原 Web 部署拓扑（Gin HTTP / Next.js / Docker / nginx / 3000·8080 端口）已随
> 桌面端迁移整体退役，本手册历史版本见文末版本表。
> 升级背景与实施记录见 [docs/48](./48-Wails-v2到v3升级评估与实施方案.md)。

## 📖 文档目的

面向**构建者/分发者**：如何把本项目构建为桌面安装器与便携 exe、如何分发与升级。
面向**终端用户**：安装、数据目录位置、命令行参数、故障排查。

## 🚀 产品形态与架构

```
namer-desktop.exe（单文件桌面应用，~37MB）
  ├ Go 壳（Wails v3）：原生窗口 WebView2 + Go 绑定层（无 HTTP 服务）
  ├ 前端：Vite + React 19 产物经 //go:embed 编译进二进制
  └ 数据：SQLite 单库 namer.db（ADR-010：测试/CI/运行期/安装包共用同一形态）
```

- **无网络依赖**：物料（字库/经典语料）在构建期全部进入 `data/namer.db` 种子库，
  运行期零 JSON 读取、零外部服务
- **单库交付**（ADR-010）：安装器只随装一份种子库 `data/namer.db`（约 22MB），
  它既是初始物料也是用户数据（收藏/历史/自学习）——卸载时保留
- 桌面架构与目录语义详见 [docs/47 §3](./47-桌面端Wails迁移方案与实施记录.md)

## 📋 环境要求

### 终端用户

- Windows 10/11 x64（WebView2 运行时缺失时安装器自动静默引导安装）
- 无其他依赖；PDF 报告内置开源字体（Noto Sans SC），开箱可用

### 构建/开发环境

| 组件 | 版本 | 说明 |
|---|---|---|
| Go | ≥1.26 | `backend/go.mod` 声明 1.26.0；wails3 CLI 自身也要求 1.26 |
| Wails CLI | **精确 v3.0.0** | `go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0` |
| Node + pnpm | Node 18+ / pnpm 12+ | 前端构建；禁用 npm/yarn |
| NSIS（makensis） | 3.x | 仅安装器需要；缺失时脚本自动跳过安装器 |
| 种子库源物料 | data/ 目录 | 构建期 `tools/build_seed` 现场制作种子库 |

> ⚠️ **pin 纪律**：Go module、wails3 CLI、`@wailsio/runtime` 三者必须同为
> `3.0.0`。v3 GA 后有 nightly/每周次版本，三者错位会导致绑定 ID 漂移
> （`quality-bindings` CI 门禁会拦截）。

## 🏗️ 构建

### 一键构建（推荐）

```powershell
# 仓库根执行
powershell -File scripts/build.ps1              # exe + 安装器 + 纯净种子库
powershell -File scripts/build.ps1 -SkipInstaller   # 只出裸 exe
powershell -File scripts/build.ps1 -Wails3Path "C:\path\to\wails3.exe"  # CLI 不在 PATH 时

powershell -File scripts/build.ps1 -Wails3Path "C:\Users\biu\tools\wails3\wails3.exe"
```

产物（`backend/bin/`）：

| 文件 | 说明 |
|---|---|
| `namer-desktop.exe` | 单文件桌面应用（约 37MB，含内置字体与前端） |
| `namer-amd64-installer.exe` | NSIS 安装器（user 作用域 + 种子库随装） |
| `namer.db` | 现场制作的**纯净种子库**（发布上传用，不含本机收藏/历史） |

脚本内部职责：CLI 定位、三重 pin 护栏、makensis 探测、种子库现场制作与校验
（构建前临时区备份开发机库、`build_seed` 制作纯净库替换打包、无论成败恢复原库）。
真正的构建逻辑只有一份，在 `backend/Taskfile.yml`（`wails3 build` / `wails3 task package`）。

### 手动分步

```powershell
# 1. 前端构建（产物由 sync-dist.mjs 自动同步进 backend/frontend/dist 供 embed）
cd frontend; pnpm install; pnpm build; cd ..

# 2. 桌面 exe（production tag 关闭 dev 特性；不带 server tag 不监听端口）
cd backend; wails3 build

# 3. NSIS 安装器（可选，需要 makensis 在 PATH）
wails3 task package
```

### 构建前注意事项

- **先关闭正在运行的 namer-desktop.exe**：避免种子库替换/恢复环节写回内存态数据
- `backend/frontend/dist/` 是构建期同步目标（构建产物占位），不要手工放源码
- 绑定接口变更后需重新生成 TS 绑定（`quality-bindings` CI 门禁校验一致性）

## 📦 分发与安装

### 方式一：NSIS 安装器（推荐）

双击 `namer-amd64-installer.exe`，或静默安装：

```powershell
namer-amd64-installer.exe /S
```

- 安装位置：`%LocalAppData%\Programs\NameMaster`（user 作用域，免管理员）
- 随装内容：`namer-desktop.exe` + `data\namer.db` 种子库
- 快捷方式：桌面 + 开始菜单（「NameMaster」）
- **卸载**：`uninstall.exe /S`——程序与快捷方式删除，**`data\namer.db`（含收藏/
  历史）与 `logs/` 保留**，重装后数据无缝延续

### 方式二：便携 exe

单文件 `namer-desktop.exe` 直接运行；数据落 exe 同级 `data/`（见下表），
整个目录可拷贝迁移（U 盘分发等）。

## ▶️ 运行与数据目录

### 数据目录语义（按来源分级，`bootstrap.DataDirSource`）

| 项 | dev（仓库内） | 打包（exe 同级 data/ / cwd/data） |
|---|---|---|
| 物料/库目录 | `-data` > `DATA_DIR` > 仓库根 data/ | `-data` > `DATA_DIR` > exe 同级 data/ > cwd/data |
| 数据库 | `-db` > `NAMER_DB_PATH` > 仓库根 namer.db | `-db` > `NAMER_DB_PATH` > data/namer.db |
| 日志 | `-log` > `NAMER_LOG_PATH` > 仓库根 logs/ | `-log` > `NAMER_LOG_PATH` > data/logs |

### 私有 / 干净数据库（-db）

| 用法 | 命令 | 行为 |
|---|---|---|
| 私有库 | `namer-desktop.exe -db D:/my/private.db` | 指向既有文件 = 使用该库，收藏/历史独立 |
| 干净库 | `namer-desktop.exe -db D:/new/clean.db` | 不存在路径 = 自动建库播种（首跑约 1~2 分钟） |

常驻切换：为 exe 建多个快捷方式，在「目标」末尾追加不同 `-db` 路径。
运行期不支持热切换（库在装配期确定，换库需重启）。详见 [docs/48 §9.11](./48-Wails-v2到v3升级评估与实施方案.md)。

### 命令行参数总表

| 参数 | 说明 |
|---|---|
| `-help` | 显示帮助 |
| `-data <dir>` | 物料数据目录 |
| `-db <path>` | SQLite 库路径（私有/干净库，见上表） |
| `-log <dir>` | 日志目录 |

## 🎨 前端构建开关

构建期 Vite 静态注入（`frontend/src/lib/featureFlags.ts`），运行期不可改：

| 开关 | 默认 | 控制 |
|---|---|---|
| `VITE_SHOW_MATERIALS` | 隐藏 | 导航「物料管理」入口（单库分发后重导无输入源，仅开发/排障开启） |
| `VITE_SHOW_JSON` | 隐藏 | 导航「JSON 美化查看器」入口（开发调试工具） |

开启方式：构建前设置环境变量（如 `$env:VITE_SHOW_JSON="true"; pnpm build`）。
路由始终可达（`/#/materials`、`/#/json-viewer`），开关只控制导航入口显隐。

## 🪵 日志与故障排查

### 日志位置

- dev：仓库根 `logs/namer-YYYYMMDD.log`（按天轮转，保留 32 天）
- 打包/安装版：exe 同级 `data/logs/`
- 内容全中文，不含敏感信息；日志系统初始化失败自动降级 stdout 不阻断启动

### 启动失败：startup-error.log 与错误代码

启动失败时 exe 同级生成 `startup-error.log` 并弹窗（Ctrl+C 可复制全文），
按错误代码反馈：

| 代码 | 类别 | 常见原因与处置 |
|---|---|---|
| E-1001 | 数据目录未找到 | 仓库/exe 同级均无 data/——用 `-data` 或 `DATA_DIR` 指定 |
| E-1002 | 数据初始化失败 | 种子库缺失必需物料 / `-db` 指向了非法文件——换库或重跑 build.ps1 |
| E-1003 | 窗口运行时失败 | WebView2 环境异常——重装 WebView2 Runtime |
| E-1999 | 未捕获 panic | 附带完整调用栈，原样反馈 |

## 🔄 维护与更新

### 版本升级

```powershell
git pull
powershell -File scripts/build.ps1     # 三重 pin 护栏会在依赖错位时拦截
# 安装新安装器覆盖安装：data/namer.db 保留，收藏/历史无缝延续
```

### 数据备份

用户数据就在一份 SQLite 文件里（WAL 模式）：

```powershell
# 建议先关闭程序，避免 WAL 未合并；直接复制即可
Copy-Item "%LocalAppData%\Programs\NameMaster\data\namer.db" D:\backup\
```

恢复：把备份放回原路径（或用 `-db` 指向备份文件启动）。
