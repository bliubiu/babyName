# 开发文档

## 一、项目概述

**项目名称**：起名（NameMaster）

**项目类型**：全栈Web应用

**技术栈**：
- 前端：Next.js 14 + React 18 + Tailwind CSS + TypeScript + Zustand
- 后端：Go 1.25+ + Gin
- 数据库：SQLite（默认）/ 内存存储（回退）
- 缓存：内存缓存（支持 Redis 扩展）
- 日志：Zap + Lumberjack（日志轮转）
- 部署：Docker + Docker Compose
- 包管理：pnpm（前端）/ Go Modules（后端）

**架构模式**：DDD（领域驱动设计）

## 四、核心功能模块

### 4.1 名字生成模块

- **功能**：根据用户输入的姓氏、性别、出生日期等信息，生成符合八字命理的名字
- **实现**：`internal/domain/name/generator.go`、`internal/domain/name/enhanced_generator.go`
- **核心函数**：`Generate(opts GenerateOptions)`、`GenerateNamesWithAnalysis(opts GenerateOptions)`
- **设计模式**：Options 模式（`GenerateOptions` 结构体替代多参数函数）
- **特性**：
  - 支持字辈功能
  - 支持五行筛选
  - 支持笔画范围筛选
  - 支持诗词经典筛选
  - 支持拼音首字母筛选
  - 三才五格正确计算
  - 增强版生成器支持详细分析

### 4.2 八字分析模块

- **功能**：分析用户的生辰八字，计算喜用神、五行等信息
- **实现**：`internal/domain/bazi/bazi.go`
- **核心函数**：`AnalyzeBazi`
- **特性**：
  - 四柱八字计算
  - 五行分布分析
  - 喜用神推算
  - 纳音五行计算
  - 黄历信息查询
  - 农历转换

### 4.3 易经卦象模块

- **功能**：根据名字笔画数计算易经卦象
- **实现**：`internal/domain/yijing/hexagram.go`
- **核心函数**：`GetHexagramByStrokes`
- **特性**：
  - 64卦完整数据
  - 卦辞、象辞、爻辞
  - 卦象匹配分析

### 4.4 紫微斗数模块

- **功能**：分析用户的紫微斗数命盘
- **实现**：`internal/domain/ziwei/ziwei.go`
- **核心函数**：`AnalyzeZiwei`
- **特性**：
  - 十四主星分析
  - 四化星分析
  - 命宫分析

### 4.5 生肖模块

- **功能**：根据出生年份确定生肖及喜忌
- **实现**：`internal/domain/zodiac/zodiac.go`
- **核心函数**：`GetZodiac`
- **特性**：
  - 12生肖完整信息
  - 相合相冲关系
  - 五行属性

### 4.6 缓存系统

- **功能**：缓存频繁计算的结果，提高响应速度
- **实现**：`internal/infrastructure/cache/cache.go`
- **核心接口**：`Cache`（Get、Set、IsNull、Delete）
- **设计模式**：依赖注入（通过构造函数注入，不再使用全局单例）
- **特性**：
  - 内存缓存（默认）
  - 支持 Redis 扩展
  - 支持过期时间和自动清理
  - Null 值缓存防止缓存穿透
  - 类型安全（Redis 存储保留类型信息）

### 4.7 名字统计模块

- **功能**：查询名字重名率和排行榜
- **实现**：`internal/domain/namestat/namestat.go`
- **核心函数**：`GetNameStats`、`GetTopNames`
- **特性**：
  - 全国重名率
  - 省份重名率
  - 热门名字排行

## 八、性能优化

### 8.1 后端优化

- **SQLite WAL 模式**：读写分离，写连接串行化，读连接池并发读
- **依赖注入**：服务层通过构造函数注入缓存和领域接口，便于测试和替换
- **缓存机制**：减少重复计算，支持 Null 值缓存防止穿透
- **日志轮转**：Lumberjack 自动轮转，单文件 100MB，保留 3 个备份，32 天过期
- **并发安全**：CORS 中间件闭包变量移入请求内部，避免竞态
- **限流保护**：IP 级别令牌桶限流，支持最大 IP 数上限，防止内存耗尽
- **优雅关闭**：支持 SIGINT/SIGTERM 信号，等待活跃请求完成

### 8.2 中间件

| 中间件 | 功能 | 实现方式 |
|-------|------|---------|
| CORS | 跨域支持 | 基于请求来源动态设置允许跨域，闭包变量移入请求内部避免竞态 |
| 限流 | 防止滥用 | 令牌桶算法，每IP独立桶，支持最大IP数上限（默认1000），防止内存耗尽 |
| 日志 | 请求记录 | 记录请求方法、路径、状态码、耗时、客户端IP |
| 恢复 | 防崩溃 | 捕获panic，记录堆栈，返回500 JSON错误 |
| RequestID | 请求追踪 | 每次请求生成唯一ID，通过响应头返回 |

### 8.3 前端优化

- 使用Next.js的静态生成和服务器端渲染

## 九、部署

### 9.1 后端部署

1. 构建可执行文件：`go build -o server cmd/server/main.go`
2. 配置命令行参数（见下表）
3. 启动服务器：`./server`

**命令行参数（基于 Viper 配置）**：

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `-port` | 服务端口 | 8080 |
| `-host` | 服务主机 | localhost |
| `-mode` | 运行模式：backend 或 all | all |
| `-static` | 前端静态文件目录 | frontend/out |
| `-db` | SQLite 数据库文件路径 | namemaster.db |
| `-log` | 日志文件路径 | name.runlog |
| `-log-level` | 日志级别（debug/info/error） | info |
| `-rate-capacity` | 令牌桶容量 | 100 |
| `-rate-rate` | 令牌生成速率（每秒） | 10 |
| `-config` | 配置文件路径 | application.yml |

### 9.2 前端部署

1. 构建生产版本：`pnpm build`
2. 部署到Vercel或其他静态网站托管服务
3. 配置域名和HTTPS

### 9.3 Docker部署

```yaml
# docker-compose.yml
version: '3.8'

services:
  backend:
    build: ./backend
    ports:
      - "8080:8080"
    volumes:
      - namemaster-data:/data    # SQLite 数据持久化
      - namemaster-logs:/app/logs # 日志持久化
    command: ["./server", "-mode", "all", "-db", "/data/namemaster.db"]

  frontend:
    build: ./frontend
    ports:
      - "3000:3000"
    depends_on:
      - backend

volumes:
  namemaster-data:
  namemaster-logs:
```
