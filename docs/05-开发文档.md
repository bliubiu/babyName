# 开发文档

## 一、项目概述

**项目名称**：宝宝起名大师（NameMaster）

**项目类型**：全栈Web应用

**技术栈**：
- 前端：Next.js 14 + React 18 + Tailwind CSS + TypeScript
- 后端：Go + Gin
- 数据库：支持 PostgreSQL / 内存存储（可选）
- 缓存：支持 Redis / 内存缓存（可选）
- 报告生成：Puppeteer
- 部署：Docker + Docker Compose

**架构模式**：DDD（领域驱动设计）

## 六、使用说明

### 6.1 名字生成流程

1. **输入信息**：填写姓氏、性别、出生日期时间
2. **八字分析**：系统自动计算八字五行、喜用神
3. **生肖属相**：确定宝宝生肖及喜忌
4. **易经起卦**：根据姓名笔画起卦解读
5. **名字生成**：基于玄学规则生成候选名字
6. **综合评分**：100分制多维度评分
7. **选择名字**：查看详情，选择心仪的名字
8. **保存记录**：自动保存到历史记录

### 6.2 评分算法

| 评分维度 | 权重 | 说明 |
|---------|------|------|
| 八字匹配度 | 30% | 名字五行与喜用神的匹配程度 |
| 纳音五行 | 20% | 名字与年命的关系 |
| 生肖适配 | 15% | 名字与生肖的相合程度 |
| 易经卦象 | 20% | 姓名卦的吉凶 |
| 读音韵律 | 10% | 名字的读音流畅度 |
| 寓意内涵 | 5% | 汉字的寓意美好程度 |

## 七、玄学知识

### 7.1 八字五行

八字由年柱、月柱、日柱、时柱组成，每柱两天干+一地支。

**天干**：甲乙丙丁戊己庚辛壬癸
- 甲乙 → 木
- 丙丁 → 火
- 戊己 → 土
- 庚辛 → 金
- 壬癸 → 水

**地支**：子丑寅卯辰巳午未申酉戌亥

### 7.2 纳音五行

60甲子，每个年份对应不同的纳音：
- 甲子、乙丑 → 海中金
- 丙寅、丁卯 → 炉中火
- ...（共60种）

### 7.3 生肖属相

12生肖：鼠牛虎兔龙蛇马羊猴鸡狗猪

**相合**：鼠-牛、虎-猪、兔-狗、龙-鸡、蛇-猴、马-羊
**相冲**：鼠-马、牛-羊、虎-猴、兔-鸡、龙-狗、蛇-猪

### 7.4 易经64卦

根据姓名总笔画数起卦：
- 上卦 = (总笔画数 - 1) % 8 + 1
- 下卦 = (总笔画数) % 8 + 1
- 动爻 = (总笔画数) % 6 + 1

## 八、常见问题

### Q1: 为什么选择内存存储而不是数据库？
A: 内存存储模式零依赖、启动快，适合开发测试和小型部署。数据量完全可以存储在内存中。

### Q2: 如何添加新的汉字到名字库？
A: 修改 `backend/internal/domain/name/generator.go` 中的汉字列表。

### Q3: 评分标准可以调整吗？
A: 可以修改 `generator.go` 中的评分权重参数。

### Q4: 支持自定义卦象解读吗？
A: 可以修改 `backend/internal/domain/yijing/hexagram.go` 中的卦象数据。

### 7.4 玄学计算核心算法

#### 八字计算流程

```
输入: 年、月、日、时(时辰)
  │
  ▼
1. 转换年柱 (天干地支)
   - 根据年份获取天干
   - 根据年份获取地支
   - 确定年柱
  │
  ▼
2. 转换月柱
   - 根据年份获取月令
   - 根据年份和月份获取月柱天干
   - 确定月柱
  │
  ▼
3. 转换日柱
   - 使用蔡勒公式计算星期
   - 推算日柱天干地支
  │
  ▼
4. 转换时柱
   - 根据时辰获取时柱
   - 确定时柱天干
  │
  ▼
5. 分析五行
   - 统计各五行数量
   - 判断日主强弱
   - 计算喜用神
  │
  ▼
输出: 完整八字分析结果
```

## 八、部署方案

### 8.1 Windows EXE 运行（最简方式 - 推荐）

直接运行编译好的可执行文件，无需任何依赖。

```bash
# 方式一：双击运行
# 下载 release 版本的 namemaster.exe
# 双击 namemaster.exe 即可启动

# 方式二：命令行运行
.\namemaster.exe

# 方式三：指定端口运行
.\namemaster.exe -port 8080

# 方式四：前端+后端一体化运行（前端嵌入）
.\namemaster.exe -mode all
```

**配置参数**：

| 参数 | 说明 | 默认值 |
|------|------|--------|
| -port | 后端服务端口 | 8080 |
| -mode | 运行模式: backend(仅后端) / all(前后端一体) | backend |
| -host | 服务监听地址 | localhost |
| -static | 前端静态文件目录(仅all模式) | ./frontend/.next |

**访问方式**：
- 仅后端模式：后端运行在 http://localhost:8080，前端需单独启动
- 一体化模式：直接访问 http://localhost:8080 即可使用完整功能

### 8.2 Docker Compose配置（默认内存模式）

```yaml
version: '3.8'

services:
  backend:
    build: ./backend
    ports:
      - "8080:8080"
    # 无需数据库依赖，内存存储模式

  frontend:
    build: ./frontend
    ports:
      - "3000:3000"
    depends_on:
      - backend
```

### 8.2 Docker Compose配置（生产模式-可选）

```yaml
version: '3.8'

services:
  backend:
    build: ./backend
    ports:
      - "8080:8080"
    environment:
      - STORAGE_MODE=postgres
      - DATABASE_URL=postgres://user:pass@db:5432/namemaster
      - REDIS_URL=redis://redis:6379
    depends_on:
      - db
      - redis

  frontend:
    build: ./frontend
    ports:
      - "3000:3000"
    depends_on:
      - backend

  db:
    image: postgres:15
    environment:
      - POSTGRES_USER=user
      - POSTGRES_PASSWORD=pass
      - POSTGRES_DB=namemaster
    volumes:
      - postgres_data:/var/lib/postgresql/data

  redis:
    image: redis:7
    volumes:
      - redis_data:/data

volumes:
  postgres_data:
  redis_data:
```

### 8.3 部署步骤

```bash
# 默认模式（内存存储，无需数据库）
docker-compose up -d

# 查看日志
docker-compose logs -f

# 停止服务
docker-compose down
```
