## 设计方案

### 核心思路：通用 ContentEntry 适配器

现有 `poemEntry` 接口 `{GetTitle, GetContent, GetSource}` 已经足够通用。
只需要为每种 JSON 格式定义一个**适配器类型**，实现这个接口，
然后统一传入 `extractFromEntry()`。

### 方案 A：通用章节适配器（覆盖 80% 文件）

多数文件结构为 `{content: [{chapter, paragraphs: []string}]}`，
只需一个通用适配器即可覆盖。

```go
// ClassicSection 通用篇章适配器（覆盖大多数经典文本）
type ClassicSection struct {
    Title    string
    Content  []string
    Source   string
}

func (s ClassicSection) GetTitle() string     { return s.Title }
func (s ClassicSection) GetContent() []string  { return s.Content }
func (s ClassicSection) GetSource() string     { return s.Source }
```

**覆盖范围**：lunyu, mengzi, daxue, zhongyong, sanzijing, qianziwen,
dizigui, youxueqionglin, zengguangxianwen, shenglvqimeng, qianjiashi,
wenzimengqiu, zhuzijiaxun, guwenguanzhi

### 方案 B：诗词阵列适配器（覆盖 shici / cifu / yuanqu / yuefu）

这些文件是 JSON 数组，每项包含 `paragraphs: []string`（或 `content: []string`）。

```go
// ShiCiSection 诗词条目适配器（shici.json 格式）
type ShiCiSection struct {
    Title    string   `json:"title"`
    Author   string   `json:"author"`
    Dynastry string   `json:"dynasty"`
    Type     string   `json:"type"`
    Para     []string `json:"paragraphs"`
    Source   string   `json:"source"`
}

func (s ShiCiSection) GetTitle() string     { return s.Title }
func (s ShiCiSection) GetContent() []string { return s.Para }
func (s ShiCiSection) GetSource() string    { return "唐诗宋词" }
```

### 核心提取函数泛化

```go
// extractFromEntries 从任意实现 poemEntry 的切片中提取起名用字
func extractFromEntries(entries []poemEntry, seen map[string]*PoetryChar) {
    for _, entry := range entries {
        // paragraph 模式：直接拼接
        contentType := reflect.TypeOf(entry.GetContent())
        if len(entry.GetContent()) > 0 && isParagraphsFormat(entry.GetContent()) {
            extractFromEntry(entry.GetTitle(),
                mergeParagraphs(entry.GetContent()),
                entry.GetSource(), seen)
        } else {
            extractFromEntry(entry.GetTitle(),
                entry.GetContent(),
                entry.GetSource(), seen)
        }
    }
}
```

### 加载函数注册模式

```go
// 统一的文件分类 → 提取函数映射
type classicFileDef struct {
    filename string       // JSON 文件名
    source   string       // 来源名称（显示用）
    priority int          // 0=P0, 1=P1, 2=P2, 3=P3
    loader   func(string, string, map[string]*PoetryChar) error
}

// LoadFromJSON 扩展后调用所有注册的加载器
func LoadFromJSON(dataDir string) error {
    for _, def := range classicFilesOrdered {
        if err := def.loader(dataDir, def.source, allSeen); err != nil {
            logger.Warn("加载 %s 失败: %v", def.filename, err)
            continue
        }
    }
    return nil
}
```

```go
// 替代 extractPoetryChars 和 extractChuCiChars
func extractFromEntries(entries []poemEntry, seen map[string]*PoetryChar) {
```

- 需要增量去重而非全部加载到内存后去重

## 风险与注意事项

1. **shici.json 解析性能**：6.7MB / 12064 条，建议在 goroutine 中解析，
   或者使用流式解析避免阻塞启动。

2. **内存占用**：全部提取后，`PoetryChar` 数组可能扩张到 2-3 万条，
   每条约 200 字节，总计约 4-6MB，可接受。

3. **去重策略**：不同来源可能包含相同汉字（如「思」「悠」同时出现在诗经和唐诗中），
   `poetryIdx` 的 `map[string][]PoetryChar` 天然支持一字多源，无需过度去重。

4. **汉字属性缺失**：部分古文字不在 `hanzi.HanziData` 中，
   现有逻辑已处理此情况（默认 `Pinyin=""`, `Wuxing=""`, `Gender="通用"`）。

5. **停用词表扩展**：当前停用词表主要面向文言虚词。
   扩展至 shici 后，可能需要补充少量诗词中常见的语气词。
