# UI 设计工艺深化计划（frontend-design × hallmark × impeccable 方法论）

## Context

用户要求参考 Nutlope/hallmark（三层门槛 Floor/Reflex/Finish + 反套路清单 + 任务导向）与 pbakaus/impeccable（critique/audit 评审 + PRODUCT/DESIGN 上下文文档）优化 UI 设计与交互体验。

**现状盘点结论**：现有设计系统成熟度中上——象牙白/水墨/玉绿/朱红 CSS 变量色板（暗色已变量化）、Noto Sans/Serif SC 双字体、印章/卷轴/墨晕/心形回弹动画族、focus-visible 与 prefers-reduced-motion 已处理、结果页已有骨架屏与进度条。**这是工艺深化任务（evolution），不是推翻重做**。美学方向定为**深化"文人纸卷"中国风**：字排对比、留白节奏、纸张质感、印章体系化、动效减量而精准。

**范围**：试点先行——首页（HomeContent/NameForm）+ 结果页（result/page + NameCard/NameFilter/CompareTray）两大核心页面，验收后下一轮铺开其余页面。全程保住测试锚点（e2e 26 例的 aria-label/文案不变）。

## 实施内容（4 个 commit）

### C1 设计上下文文档 + Floor 硬门槛核对（P0）

1. **`frontend/DESIGN.md`**（impeccable document 式）：记录现有视觉系统——色板（含变量 RGB 值）、字体族与字排规范（标题 serif tracking-widest/正文行高）、动画族与缓动约定、卡片/表单/导航组件模式、暗色变量方案——后续迭代与 AI 协作的单一真相源
2. **Floor 核对与修复**（逐项过 hallmark 底线清单）：
   - 对比度：扫 `text-ink/50`、`text-gold-dark/70`、`text-jade/60` 等低透明度文字的实际对比度，低于 4.5:1（正文）/3:1（大字）的提档
   - 暗色模式：globals.css 的 dark 变量段与组件层适配逐页核对（NameCard/NameFilter/CollapsibleSection 在暗色下的实际表现），补缺口
   - 动效：全站动画挂 `motion-reduce:` 或确认 reduced-motion 块覆盖（globals.css L704 已有块，核对覆盖面）

### C2 首页工艺深化（HomeContent.tsx / NameForm.tsx / globals.css home-* 段）

3. **hero 题签化**：`home-kicker`（"传统命理 · 智能择名"）从西式 eyebrow 改为竖排引首题签样式（书写方向 vertical + 印章色细边），避开 hallmark 点名的套路化 eyebrow；`home-hero-mark`"如意"印章扩展为可复用的印章组件（`.seal-mark`）
4. **表单节奏**：必填区/高级区的分隔与留白精修（间距 token 化）、字段标签字排统一、错误态文案位置与动效（shake 微反馈）、提交按钮仪式感（按压 scale + 进度态与按钮态联动视觉）
5. **移动端核对**：390px 宽度下表单两列折叠/进度条/高级面板的布局

### C3 结果页工艺深化（result/page.tsx / NameCard.tsx / NameFilter.tsx / CompareTray.tsx）

6. **评分印章体系化**：把 NameCard 的裸分数升级为印章式徽章（复用 seal-red/印章形制——分数等级映射：≥95 朱红章 / 90-95 金章 / 其余墨字），层级：名字大字 > 印章分 > 五行标签
7. **五行标签体系化**：wuxing 五色板已有，统一 chip 形制（色点 + 字）、对比页与卡片的标签同构
8. **信息密度分区**：名字主列（名/拼音/粤拼）与命理副列（八字标签/卦象 chip）视觉分组；筛选面板（NameFilter）与对比托盘（CompareTray）的过渡动效统一缓出曲线
9. **空态设计**：收藏/筛选无结果的空态从纯文案升级为Illustration-less 印记式空态（大字号"空"印章 + 引导文案）

### C4 浏览器多宽度验收 + 全量回归

10. **多宽度渲染检查**（hallmark sloplint 思路）：browser-use 驱动 server-build 版页面，390/768/1280 三宽度截图验收首页与结果页（含暗色切换），新视角审查反套路清单
11. **全量回归**：e2e 26 例（锚点不动）+ vitest 180 例 + tsc + go test 不受影响确认；若有锚点必须改动的（如按钮结构），先改测试后改实现

1. vitest 180 例 + e2e 26 例全绿（锚点不变）
2. browser-use 三宽度截图：首页/结果页（明暗两态）人工确认无布局破坏
3. Floor 清单逐项核对记录（对比度数值、暗色截图、reduced-motion 覆盖面）
4. 每批 commit 前跑 `pnpm build`（sync-dist 产物同步）确保可出包

## 不做

- 不换设计方向/不推翻现有色板与字体（evolution）
- 不动 e2e/vitest 既有断言锚点（aria-label、可见文案）——确需变更的先改测试
- 其余 9 页（测名/黄历/收藏/对比/历史/stat/分享等）本轮不动，留下一轮
